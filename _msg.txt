Fix picking, split upscale/caption concurrency, and add thumbnails

Three problems reported after the project rewrite, plus what a full pass
over the logic turned up.

Picking never worked
- Clicking a card called selectFile only; the picked set was read when
  rendering but never written, so the checkboxes stayed empty and the
  run buttons always processed the whole folder.
- Clicking now toggles selection, double-click opens the preview, and
  the header gains 全选 / 清除 with a live 已选 N count. The run buttons
  relabel to 放大 N 张 once anything is picked.
- A selection is sent as params.paths with force, so exactly those files
  run and existing results are overwritten rather than skipped.

Concurrency split
- Upscaling stays strictly serial: it runs as one step inside the single
  executor thread and walks the list one image at a time, because the GPU
  only fits a single model pass.
- Captioning keeps its internal thread pool, sized from the project's
  concurrency setting, so several model requests are in flight at once
  while the job itself still occupies the one queue slot.

Removed the leftover parallel paths
- The old /api/pipeline/* and /api/upscale/start|stop|clear|batch
  endpoints were still registered alongside the new executor and still
  wrote to their own batch state, which is exactly the shape of the
  original bug. They are gone, along with their workers; a stray stack of
  decorators left by that removal is cleaned up too.

Thumbnails
- The grid was loading originals: 49 images at ~1.3MB each, roughly 61MB
  for one screen, which is why most cards rendered blank. A /api/thumb
  endpoint now downscales to 320px and caches on disk, taking that screen
  to about 490KB, and the cache is trimmed at startup. Previews and the
  compare slider still request the full-size original.

Restored entries that the rewrite dropped
- Project dialog gains person name, generic subject, style hint, extra
  instructions, shot-tags and auto-rename.
- Header regains 质检 / 替换 / 改名, wired to the existing endpoints.
- Deleting a project now refuses while that project still has work queued
  or running, instead of silently orphaning the job.

Verified: picking two of four images upscaled exactly those two and then
captioned exactly two, serial execution held at one job at a time across
three projects, and all 49 thumbnails load. 38 checks pass.
